# Изменения форка (stability-fork)

Источники не трогались — правки касаются только работы самого аддона.

## Стабильность

| Проблема | Где | Что сделано |
|---|---|---|
| Каталог реплеев запускал полный синк всех провайдеров на каждый запрос (межсезонье, пустые хабы), параллельно | `catalog.js`, `MatchAggregator.js` | Single-flight синк: все вызовы делят один; из запроса синк ждётся только при полностью пустом кэше и не дольше 20 с |
| Один зависший провайдер навсегда блокировал синк (`syncing === true`) | `MatchAggregator._fetchProviderMatches`, `CronService` | Дедлайн на провайдера (`PROVIDER_SYNC_TIMEOUT_MS`, 90 с) + watchdog флага синка |
| Неограниченный запуск процессов `node` (по процессу на вариант стрима) → OOM/524 | новый `services/childProcessLimiter.js` | Глобальный лимит (`CHILD_PROC_MAX`), очередь с таймаутом, склейка одинаковых запусков, `process.execPath`, SIGKILL по таймауту, compile cache |
| `safeFetch`: таймаут не отменял запрос impit, тело ответа читалось без таймаута, abort клиента не доходил | `impitClient.js` | Таймаут и `signal` передаются в impit, чтение тела под тем же дедлайном, по умолчанию 2 попытки вместо 3 |
| `/api/cache/*` резолвера был публичным → подмена стримов в кэше | `index.js`, `deploy/Caddyfile` | Закрыт на уровне приложения и прокси |
| `onError`/`logLevel` игнорировались http-proxy-middleware v4 | `index.js` | Обработчик ошибок через `on.error`, таймауты прокси |
| fastmp4: вечное ожидание `drain` после ухода клиента | `routes/streamProxy.js` | Ожидание `drain` или `close` |
| mp4proxy: загрузка не прерывалась при уходе клиента, нет таймаута | `routes/streamProxy.js` | AbortController + `pipeline` |
| hlschunk: `.pipe()` без обработки ошибок → uncaughtException | `routes/streamProxy.js` | `pipeline` |
| SIGTERM обрывал все трансляции мгновенно | `index.js`, `resolverManager.js` | Graceful drain (`SHUTDOWN_GRACE_MS`), затем остановка резолвера |
| `uncaughtException` молча проглатывался навсегда | `index.js` | Логируется; при 5+ за минуту — чистый перезапуск |
| Двойной синк при старте | `CronService.js` | Убран дубль |
| Тестовые/документационные IP (192.0.2.x и др.) встраивались в карточки | `EmbedBase.js` | Добавлены в недоступные диапазоны (чинит 2 падающих теста) |

## Задержка

| Было | Стало |
|---|---|
| Готовый список стримов ждал DaddyLive до 15 с | Ответ через `STREAM_FIRST_RESULT_GRACE_MS` (1,5 с) после первого рабочего стрима; DaddyLive ждём максимум `STREAM_PRIORITY_WAIT_MS` (4 с) |
| Speed probe качал ~512 КБ на каждый стрим до ответа | Выключен по умолчанию (`ENABLE_SPEED_PROBE=true` вернёт) |
| Live-плейлист кэшировался до 3 с → отставание от эфира | 0,5–1 с (¼ target duration) |
| Любая ошибка плейлиста → 404 всем зрителям на 15 с | stale-if-error: при временном сбое отдаётся последний рабочий плейлист (12 с); негативный кэш 4 с |
| Fetch плейлиста мог висеть ~40 с | 1 попытка, 6 с, один быстрый ретрай |
| Каждый запрос — новое TCP/TLS-соединение после короткого idle | keep-alive 65 с |
| Нет сжатия; переписывание URL парсило 2,5 МБ JSON на каждый запрос | gzip/brotli; мемо переписанных ответов |
| Пересборка всех страниц каталога после каждого обновления логотипов; «стадо» на промахе | stale-while-revalidate по логотипам + single-flight сборки |
| DNS-запрос на каждый сегмент/манифест | Кэш 60 с для успешных ответов |
| Кэш стримов на 200 записей | 1000 (`RESOLVE_CACHE_MAX_ENTRIES`) |
| Каждый запрос аддона проходил 6 `express.static` | Статика пропускается для API/аддон-путей |
| Cluster из 2 воркеров (2 кэша плейлистов, опрос диска) | Один процесс; опрос диска только в multi-process |

## Ретрансляция сегментов (`PROXY_ALL_SEGMENTS`, по умолчанию включено)
Видеосегменты, ключи AES и init-сегменты fMP4 идут через `/api/hlschunk` твоего сервера, а не напрямую с CDN. Это решает три проблемы: блокировку CDN у провайдера, требование браузерных заголовков (Referer/User-Agent) и голые `http://`-сегменты. Заодно:
- `/api/hlschunk` идёт по редиректам CDN (раньше плееру отдавался 3xx без `Location`);
- режим `raw=1` передаёт байты и `Content-Type` без изменений (fMP4/AAC/ключи больше не прогоняются через «раскрытие» TS);
- относительные `URI` в `EXT-X-KEY` и `EXT-X-MEDIA` раньше разрешались относительно адреса аддона и давали 404 (ломались зашифрованные потоки и отдельные аудиодорожки). Теперь ключи становятся абсолютными, а аудиоплейлисты идут через `/api/manifest`.

Цена — трафик VPS: 3–8 Мбит/с на зрителя. `PROXY_ALL_SEGMENTS=false` вернёт прямую раздачу с CDN.

- Гербы команд из TheSportsDB не грузились: старый бесплатный ключ `3` отключён (403). Ключ вынесен в `THESPORTSDB_API_KEY` (по умолчанию `123`), запросы ограничены по частоте (`THESPORTSDB_RPM`).

## Прокси
`OUTBOUND_PROXY_URL` (socks5/http) направляет весь исходящий трафик аддона — node http/https, undici, встроенный fetch,
impit и дочерние процессы (расшифровка, резолвер) — через один прокси с удалённым DNS; локальные хосты идут напрямую.
`src/providers/outboundProxy.js`, `docker-compose.xray.yml`, `deploy/xray-add-inbound.py`, тесты `tests/outboundProxy.test.js`.
